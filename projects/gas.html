무엇을 익히려 했나

스킬 시스템을 캐릭터 클래스에 직접 구현하면 스킬이 늘어날수록 캐릭터가 비대해지고, 쿨다운·자원 소모·상태이상 같은 공통 규칙이 스킬마다 중복됩니다. GAS가 그걸 어떻게 나누는지 손으로 확인하는 것이 목표였습니다.

핵심은 어빌리티가 피해량을 직접 깎지 않는다는 점입니다. 어빌리티는 GameplayEffect를 “적용”할 뿐이고 실제 수치 변경은 AttributeSet이 처리합니다. 덕분에 밸런스 수정이 코드가 아니라 데이터(GE 에셋) 쪽으로 넘어갑니다.

기능 01

어빌리티 · 이펙트 · 태그 세 축으로 분리

무엇을 하는가 / 무엇이 변하는가 / 지금 어떤 상태인가.

구현

  • GameplayAbility — 무엇을 하는가. GASTraceDamageAbility가 전방 트레이스로 대상을 찾습니다.
  • GameplayEffect — 무엇이 변하는가. 피해량 · 마나 비용 · 쿨다운을 각각 별도 GE로 두었습니다.
  • GameplayTag — 지금 어떤 상태인가. State.Stunned, Cooldown.Q 같은 태그로 활성화를 막습니다.
  • GAS 흐름 자체를 검증하려고 GASTestDamageAbility(자기 피해 스킬)를 따로 만들어 먼저 돌렸습니다.

화면

촬영 권장 — QWER 스킬 사용 화면

스킬을 쓰는 순간의 게임 화면과 HUD(체력·마나·쿨다운). 학습 프로젝트라도 돌아가는 모습이 한 장 있으면 설명이 붙습니다.

어려움

문제
처음에는 스킬 로직을 캐릭터 클래스에 직접 넣었습니다. 스킬이 넷으로 늘자 쿨다운·마나 검사·피해 계산이 스킬마다 똑같이 복제됐습니다.
원인
“무엇을 하는가”와 “무엇이 변하는가”를 한 곳에서 처리했기 때문입니다. 공통 규칙이 있어도 붙일 자리가 없었습니다.
해결
어빌리티가 수치를 직접 건드리지 않게 하고 GE 적용만 하도록 바꿨습니다. 그러자 피해량·비용·쿨다운이 데이터가 되고, 밸런스 조정이 코드 수정에서 에셋 수정으로 내려갔습니다.

성과

밸런스 수정이 코드 밖으로 스킬 간 공통 규칙 중복 제거
기능 02

어트리뷰트 클램프 — 두 경로를 다 막다

하나만 막으면 다른 쪽으로 값이 새어 나갑니다.

구현

  • Health / MaxHealth / Mana / MaxMana 네 개를 정의하고, 변경 지점 두 곳을 모두 막았습니다.
  • PreAttributeChange — 값이 바뀌기 직전 모든 경로에서 호출됩니다. MaxHealth가 줄었을 때 Health를 따라 줄이는 등 값 자체의 유효성 보정에 씁니다.
  • PostGameplayEffectExecute — Instant GE가 실행된 뒤 호출됩니다. 실제 피해가 적용된 결과를 0~Max로 클램프하고 사망 판정 같은 후처리를 합니다.

화면

어려움

문제
체력을 0~Max로 제한했는데도 어떤 경로로는 범위를 벗어난 값이 들어왔습니다. 막은 것 같은데 새고 있었습니다.
원인
GAS에서 어트리뷰트가 바뀌는 경로가 하나가 아니기 때문입니다. Instant GE는 즉시 실행되고, Duration/Infinite GE는 지속 중 계속 값을 밀며, 코드에서 직접 Setter를 호출할 수도 있습니다. 훅 하나로는 이 셋을 다 잡지 못합니다.
해결
두 훅을 역할을 나눠 함께 썼습니다. PreAttributeChange는 값의 유효성 보정, PostGameplayEffectExecute는 GE 실행 결과의 클램프와 사망 판정. 어디서 값이 바뀌는지를 먼저 세어본 것이 해결의 절반이었습니다.

성과

모든 변경 경로에서 범위 보장 사망 판정을 한 자리로
기능 03

쿨다운을 타이머가 아니라 태그로

상태를 값으로 들고 있지 않으면 조건문이 늘지 않습니다.

구현

  • 쿨다운을 캐릭터의 타이머 변수가 아니라 Cooldown.Q 같은 태그의 존재 여부로 표현했습니다.
  • 쿨다운 GE가 적용되는 동안 그 태그가 붙어 있고, 어빌리티는 해당 태그가 있으면 활성화되지 않습니다.
  • 기절 같은 상태이상도 같은 방식입니다 — State.Stunned가 붙어 있으면 발동이 막힙니다.

어려움

문제
스킬을 하나 추가할 때마다 캐릭터 클래스에 쿨다운 변수와 조건문이 하나씩 늘었습니다. QWER 넷이면 넷, 여기에 기절·침묵 같은 상태가 붙으면 곱으로 늘어납니다.
원인
“지금 쓸 수 있는가”를 캐릭터가 들고 있는 값들의 조합으로 판단했기 때문입니다. 조건이 늘면 판단 코드도 같이 늘어납니다.
해결
상태를 태그의 유무로 바꿨습니다. 어빌리티마다 “이 태그가 있으면 못 쓴다”만 선언해두면, 쿨다운이든 기절이든 침묵이든 같은 메커니즘으로 처리됩니다. 캐릭터 클래스는 더 이상 개별 스킬의 사정을 모릅니다.

성과

스킬이 늘어도 캐릭터 클래스에 조건문이 늘지 않음 쿨다운과 상태이상을 같은 방식으로 처리
