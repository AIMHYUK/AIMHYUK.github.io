Bounce Hero : 꿈돌이

대전관광공사 마스코트를 주인공으로 한 모바일 점프 게임입니다. Google Play와 App Store 양쪽에 출시했고, 라이브 운영까지 참여했습니다.

어떤 게임인가

대전관광공사의 마스코트 꿈돌이가 발판을 밟고 위로 올라가는 캐주얼 점프 게임입니다. 대전관광공사와 협업한 프로젝트라 오프라인 축제 현장에서도 시연했습니다.

사수와 둘이서 0부터 만든 게임입니다. 프로토타입부터 스토어 배포, 그리고 출시 후 라이브 운영까지 전 과정을 함께 했습니다.

기획이 정해진 상태에서 코드를 얹은 것이 아니라, 만들면서 문제를 발견하고 구조를 바꿔가며 완성했습니다. 실제 이용자에게 나간 제품을 처음부터 끝까지 겪은 경험입니다.

기능 01

오브젝트 풀링으로 프레임 확보

라이브 중 발생한 프레임 드랍의 원인을 먼저 측정하고, 그다음에 구조를 바꿨습니다.

구현

  • 프로파일러로 프레임 드랍 구간을 잡아, 원인이 Instantiate/Destroy 반복에 따른 GC 부하임을 특정했습니다.
  • 발판·이펙트 등 반복 생성되는 오브젝트를 풀에서 꺼내 쓰고 되돌리는 방식으로 바꿨습니다.
  • 재사용 시점에 위치 · 애니메이션 · 타이머 상태를 함께 초기화하도록 설계에 포함했습니다.

화면

촬영 필요 — 사진 1 · 플레이 화면

꿈돌이가 발판을 밟고 올라가는 실제 게임 화면. 발판과 이펙트가 여러 개 떠 있는 순간이면 풀링 대상이 무엇인지 보입니다. 스토어 페이지의 스크린샷을 그대로 써도 됩니다.

촬영 권장 — 사진 2 · 프로파일러

Unity Profiler에서 GC Alloc 스파이크가 보이는 화면. 남아 있다면 “추측이 아니라 측정으로 원인을 잡았다”는 말의 가장 강한 증거입니다.

어려움

문제
풀링을 넣은 뒤 꺼내 쓴 오브젝트가 이전 상태를 그대로 들고 나왔습니다. 위치가 엉뚱한 곳에서 시작하거나, 이전 애니메이션이 이어서 재생됐습니다.
원인
Destroy는 오브젝트를 없애지만 풀링은 비활성화했다가 다시 켜는 것이라, 컴포넌트에 남아 있던 값이 초기화되지 않습니다. 생성과 재사용은 같은 일이 아니었습니다.
해결
풀에서 꺼내는 시점을 명시적인 초기화 지점으로 두고, 위치·애니메이션·타이머를 거기서 함께 되돌리도록 했습니다. 지워지는 것에 기대던 처리를 전부 그 자리로 옮겼습니다.

성과

저사양 안드로이드 60 fps 유지 원인 특정 → 구조 변경 순서로 처리
기능 02

플랫폼 SDK 연동과 라이브 운영

인증·결제·광고를 붙이고, 축제 현장에서 받은 피드백을 패치로 넣었습니다.

구현

  • Firebase Auth와 Realtime Database로 계정과 기록을 처리했습니다.
  • IAP 인앱 결제와 AdMob 보상형 광고 SDK를 연동했습니다.
  • 오프라인 축제 현장에서 수집한 피드백을 버그 수정과 레벨 밸런스 패치에 반영했습니다.

화면

어려움

미작성
이 기능의 트러블슈팅은 아직 정리하지 않았습니다. SDK 연동에서 막혔던 것(광고 콜백 타이밍, 결제 검증, Firebase 규칙, 심사 반려 등)이 있었다면 문제 / 원인 / 해결 세 칸에 맞춰 알려주시면 채웁니다.

함께

ZOMVIRUS — 기존 출시작 참여

같은 인턴십에서 참여한 두 번째 프로젝트입니다. 신규 출시가 아닙니다.

구현

  • 디몽이 2025년 2월에 이미 Steam에 출시한 PC VR 좀비 서바이벌 게임입니다. 제가 합류한 것은 그 뒤이며, 기능 추가와 리팩터링으로 참여했습니다.
  • 게임 내 이벤트에 연동되는 Steam Achievement를 구현했습니다.
  • 무기 장착·인벤토리 레거시 코드를 파악해 무기 슬롯을 추가하며 리팩터링했습니다.

화면

어려움

문제
무기 장착과 인벤토리가 이미 서비스 중인 코드였습니다. 슬롯을 하나 늘리는 일인데 어디를 건드려야 안전한지 알 수 없었습니다.
원인
제가 쓴 코드가 아니었고, 출시된 게임이라 되돌리기 비용이 큽니다. 구조를 모른 채 고치면 기존 동작을 깨뜨립니다.
해결
먼저 레거시 코드의 흐름을 파악하는 데 시간을 썼고, 그 위에서 슬롯을 추가하며 필요한 만큼만 리팩터링했습니다. 남이 만든 구조 위에서 확장하는 방식은 이후 배달왕에서도 같은 방식으로 이어졌습니다.

성과

Steam 도전 과제 3종 연동 무기 슬롯 추가 · 레거시 리팩터링

범위와 한계

인턴십 기간에 참여한 두 프로젝트이고, 성격이 다릅니다. 꿈돌이는 사수와 둘이 0부터 만들어 출시한 신규 개발이고, ZOMVIRUS는 제가 합류하기 전인 2025년 2월에 이미 출시돼 있던 게임에 기능 추가와 리팩터링으로 참여한 것이라 출시 실적으로 세지 않습니다. 두 프로젝트 모두 아트는 팀의 것이며, 제 담당은 클라이언트 구현입니다.
