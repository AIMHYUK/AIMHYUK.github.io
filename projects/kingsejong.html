시연 영상
1. 멀티플레이어 세션 시스템
  • OnlineSubsystem의 IOnlineSessionInterface를 직접 사용해 세션 생성, 검색, 참가, 파괴 흐름을 구현했습니다.
  • 활성 OnlineSubsystem이 NULL인지 확인해 LAN 여부를 판정하고, Steam Subsystem 환경에서는 Steam 세션 설정으로 동작하도록 구성했습니다.
  • 방 생성 시 Category, Room_Name, Host_Name, 최대 인원을 OnlineSubsystem의 세션 광고 설정값으로 등록하고, 검색 결과에서 읽어 로비 UI 표시용 roomInfo 구조체로 변환했습니다.
  • Steam 서버에 한글 방 이름을 안정적으로 저장하기 위해 방 이름을 Base64로 인코딩하고, 검색 결과 표시 시 디코딩했습니다.
  • 호스트는 세션 생성 성공 후 ServerTravel로 listen server 맵을 열고, 클라이언트는 JoinSession 결과의 connect string으로 ClientTravel합니다.
  • 세션 퇴장 시 서버 RPC, Multicast RPC, Client RPC를 역할별로 분리해 모든 플레이어가 같은 로비 복귀 경로를 타도록 처리했습니다.
  • 호스트 종료나 연결 실패는 OnNetworkFailure 콜백에서 감지해 클라이언트가 고립되지 않고 로비로 복귀하도록 보강했습니다.
  • 구현 — UJJH_GameInstance에서 IOnlineSessionInterface를 보관하고, 세션 생성/검색/참가/파괴 완료 델리게이트를 등록했습니다. FOnlineSessionSettings에는 Subsystem 기준 LAN 판정, Presence, 중간 참가 허용, 공개 세션, 카테고리와 방 이름 같은 세션 광고 설정값을 넣었습니다.
  • 결과 — 로비에서 방 생성, 검색, 참가, 게임 맵 진입까지 이어지는 멀티플레이 진입 흐름을 완성했고, Run/Battle/Talk 카테고리별 맵 이동을 하나의 세션 구조로 통합했습니다.
// 실제 구현 요약 - Subsystem 기준 LAN 판정과 로비 검색용 세션 광고 설정값 구성
FOnlineSessionSettings SessionSettings;
SessionSettings.bUseLobbiesIfAvailable = true;
SessionSettings.bIsLANMatch =
    IOnlineSubsystem::Get()->GetSubsystemName() == "NULL";
SessionSettings.bShouldAdvertise = true;
SessionSettings.bUsesPresence = true;
SessionSettings.bAllowJoinInProgress = true;
SessionSettings.NumPublicConnections = PlayerCount;

SessionSettings.Set<FString>(FName("Category"), Category,
    EOnlineDataAdvertisementType::ViaOnlineServiceAndPing);
SessionSettings.Set<FString>(FName("Room_Name"), StringBase64Encode(RoomName),
    EOnlineDataAdvertisementType::ViaOnlineServiceAndPing);
// 실제 구현 요약 - 세션 성공 후 카테고리별 맵 이동과 참가자 ClientTravel
void UJJH_GameInstance::OnMyCreateSessionComplete(FName SessionName, bool Success)
{
    if (!Success) return;

    if (CategoryValue == TEXT("Run"))
        GetWorld()->ServerTravel("/Game/JJH/BetaRunningMap?listen");
    else if (CategoryValue == TEXT("Battle"))
        GetWorld()->ServerTravel("/Game/HJS/Maps/AlphaBattleMap?listen");
    else if (CategoryValue == TEXT("Talk"))
        GetWorld()->ServerTravel("/Game/KJH/Maps/KJH_CommunityMap?listen");
}

void UJJH_GameInstance::OnMyJoinSessionComplete(FName SessionName, EOnJoinSessionCompleteResult::Type Result)
{
    if (Result != EOnJoinSessionCompleteResult::Success) return;

    FString Url;
    SessionInterface->GetResolvedConnectString(SessionName, Url);
    if (!Url.IsEmpty())
        GetWorld()->GetFirstPlayerController()->ClientTravel(Url, ETravelType::TRAVEL_Absolute);
}

2. 로비 UI
  • WidgetSwitcher로 방 만들기, 방 찾기, 캐릭터 선택 화면을 전환했습니다.
  • 슬라이더로 최대 인원을 실시간 설정하고, 선택 값은 세션 생성 파라미터와 UI 텍스트에 동시에 반영했습니다.
  • 세션 검색 완료 델리게이트에서 결과 배열을 수신한 뒤 스크롤박스에 방 슬롯 위젯을 동적으로 생성했습니다.
  • 방이 꽉 찼거나 이미 시작된 상태에서는 입장 버튼을 비활성화해 잘못된 참가 요청을 줄였습니다.
3. 달리기 미니게임
  • FinishLine의 OnComponentBeginOverlap로 결승선 통과를 감지하고 GameMode에 순서를 전달했습니다.
  • 결승선 통과 순서에 따라 초성 퀴즈 기회를 부여하고, 오답이면 다음 플레이어에게 입력 권한을 넘겼습니다.
  • DataTable에서 퀴즈 데이터를 선택하고 Multicast RPC로 모든 클라이언트 UI에 같은 문제를 동기화했습니다.
  • Client RPC로 특정 플레이어의 입력 UI만 활성화해 답변 권한이 없는 플레이어의 입력을 차단했습니다.
  • 정답, 오답, 결과 화면, 로비 복귀까지 게임 진행 단계를 네트워크 이벤트 흐름에 포함했습니다.

네트워크 구조에서 배운 점
  • 문제 — 세션 로직이 GameInstance에 모여 있어 구현 속도는 빨랐지만, 실패 원인별 UI 피드백과 Delegate 해제 같은 생명주기 관리가 명확하지 않았습니다.
  • 해결 — 세션 생성/검색/참가/파괴 콜백을 기준으로 흐름을 정리하고, 호스트 종료나 연결 실패 시 로비로 복귀하는 보호 경로를 추가했습니다.
  • 개선 — 다시 만든다면 세션 상태 머신과 Dedicated Server 기준의 매치 진입 구조를 분리하고, 실패 원인을 UI까지 전달하는 에러 모델을 두겠습니다.
