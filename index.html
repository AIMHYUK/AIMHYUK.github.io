KingSejong - Unreal Multiplayer Mini Game

Unreal Engine 5 C++ OnlineSubsystem RPC Team 5
My Responsibility 멀티플레이 세션 시스템 전반, 로비 UI, 달리기 미니게임 진행, 캐릭터 선택 흐름을 담당했습니다.
핵심 구현

UJJH_GameInstance, RunningGameModeBase, ULobbyWidget, UQuizWidget

검증 범위

활성 OnlineSubsystem이 NULL인지 확인해 LAN 여부를 자동 판정하고, 방 생성, 검색, 참가, 맵 이동, 세션 종료 흐름을 확인했습니다.

  • IOnlineSessionInterface로 방 생성, 검색, 참가, 세션 종료 흐름을 구현했습니다.
  • 활성 OnlineSubsystem이 NULL이면 LAN 세션으로, Steam Subsystem 환경에서는 Steam 세션으로 동작하도록 bIsLANMatch와 bIsLanQuery를 설정했습니다.
  • 방 생성 시 Category, Room_Name, Host_Name, 최대 인원을 OnlineSubsystem의 세션 광고 설정값으로 등록하고, 검색 결과에서 읽어 로비 UI 표시용 roomInfo 구조체로 변환했습니다.
  • 호스트는 ServerTravel("Map?listen"), 클라이언트는 JoinSession 결과의 connect string으로 ClientTravel을 수행했습니다.
  • 퀴즈 진행은 서버 GameMode가 판단하고, 공통 연출은 Multicast RPC, 개별 입력 권한은 Client RPC로 분리했습니다.
  • 다음 개선은 Listen Server 구조를 Dedicated Server 기준 매치 플로우로 분리하는 것입니다.

배달왕 김족구 - Inventory / Dialogue System

Unity 6 C# MVC Yarn Spinner
MY RESPONSIBILITY 인벤토리, 퀘스트 시스템 설계, 입력 처리를 담당했습니다.
핵심 구현

InventoryModel, InventoryController, InventoryState, YarnDialogueManager, SetPlaceYarnStartNodeQuestAction

설계 기준

인벤토리는 이벤트 기반 MVC로 데이터·UI를 분리하고, 배달은 팀 퀘스트 프레임워크에 category + target 진행 이벤트만 보고하도록 결합도를 낮췄습니다.

2D 그리드 인벤토리와 마우스/게임패드 하이브리드 입력을 구현하고, Yarn Spinner 대화를 게임 로직에 연동했습니다. 팀원이 설계한 퀘스트 프레임워크를 파악해 배달 도메인을 NPC 기반에서 장소 기반으로 재설계했습니다. 입력 포커스 이동 로직은 이후 별도 Navigator 클래스로 분리할 수 있습니다.

Isekiro - Action Combat Prototype

Unreal Engine 5 C++ Blueprint Combat
MY RESPONSIBILITY 락온, 이동 보조, 패링 판정을 담당했습니다.
핵심 구현

UActorComponent 기반 락온, Timeline/Curve 그래플링 훅, URealParryBox 패리 판정

판정 기준

Dot Product로 우선 타깃을 고르고 Line Trace로 시야를 검증했으며, 패리는 타이머로 판정 윈도우와 쿨다운을 분리했습니다.

Dot Product와 Line Trace를 활용한 락온, Timeline/Curve 기반 그래플링 훅, 패링 판정과 자세 게이지 흐름을 구현했습니다. 전투 판정은 프로토타입 범위에서 검증했고, 네트워크 복제는 별도 확장 과제로 분리했습니다.

기술 구현 요약

프로젝트에서 직접 다룬 기능과, 구현 과정에서 어떤 기준으로 설계 결정을 했는지 정리했습니다.

기술 구현 내용 설계 기준
OnlineSubsystem 세션 생성, 검색, 참가, 종료, Subsystem 기준 LAN/Steam 세션 판정, 세션 광고 설정값 등록 비동기 Delegate 완료 시점 기준으로 UI 상태, 실패 처리, Delegate 정리를 함께 관리했습니다.
Travel Flow Host는 ServerTravel, Client는 ClientTravel로 실제 맵 진입 분리 세션 참가 성공과 실제 맵 입장을 분리해 실패 지점을 추적할 수 있게 했습니다.
RPC GameMode 판단, PlayerController RPC 허브, UI 개별 갱신 권한이 필요한 판단은 서버, 공통 연출은 Multicast, 개별 UI 갱신은 Client RPC로 분리했습니다.
Combat Targeting Dot Product 기반 우선순위와 Line Trace 시야 검증 카메라 전방 각도로 후보를 고르고, 시야 검증으로 벽 뒤 대상 선택을 방지했습니다.
Action Movement 그래플링 훅의 사전 지형 검증, Curve 이동, Cable Component 연출 예측 가능한 도착점과 연출 동기화를 위해 지형 검증 후 Curve 보간으로 이동을 제어했습니다.
Combat Timing 패링 타이밍, 충돌 채널 전환, TimeDilation 연출 판정 가능 시간, 쿨다운, 연출을 분리해 프레임 의존성과 입력 체감 문제를 줄였습니다.
